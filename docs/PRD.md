 # 心灵之窗护眼助手 PRD

## 1. 文档信息

- 产品名称：心灵之窗护眼助手
- 文档版本：v0.5
- 文档状态：开发基线（MVP + 休息增强 + 多屏覆盖 + 打包安装，P1/P2 修复均通过自动化验收，见第 11 节）
- 更新时间：2026-11-07
- 目标平台：桌面应用，优先支持 macOS，并保留 Windows 扩展能力

## 2. 背景与问题

用户近期连续使用电脑时间过长，出现眼睛干涩、视力下降和散光困扰。现有提醒方式容易被忽略，因此需要一个常驻桌面应用，在工作过程中主动提醒休息，并在用户持续忽略时进入 5 分钟强制休息流程。

本产品用于建立规律休息习惯，不提供医疗诊断、视力评估或治疗建议。

## 3. 产品目标

1. 连续工作 30 分钟时及时提醒用户休息。
2. 用户忽略提醒并继续工作到 40 分钟时，进入 5 分钟强制休息。
3. 在休息期间提供低刺激的护眼训练和小游戏，降低用户继续盯屏的意愿。
4. 通过本地统计帮助用户了解工作与休息习惯。

## 4. 用户与使用场景

### 4.1 目标用户

- 长时间使用电脑办公、学习或创作的人。
- 容易忽略休息提醒的人。
- 希望通过固定节奏改善用眼习惯的人。

### 4.2 典型场景

用户启动应用并开始工作计时。工作达到 30 分钟时收到重要提醒，可以立即休息、延后 5 分钟或继续工作。如果用户继续工作，到 40 分钟时应用打开全屏置顶的休息界面，倒计时 5 分钟后才进入下一轮工作。

## 5. 核心流程

```text
启动应用
  -> 开始工作计时
  -> 30 分钟：重要提醒
       -> 立即休息
       -> 延后 5 分钟
       -> 继续工作
  -> 40 分钟：强制休息 5 分钟
  -> 休息训练或小游戏
  -> 休息完成
  -> 开始下一轮工作计时
```

## 6. 功能需求

### 6.1 工作计时

主界面需要展示：

- 当前状态：未开始、工作中、提醒中、休息中、已暂停。
- 当前连续工作时长。
- 距离 30 分钟提醒的剩余时间。
- 距离 40 分钟强制休息的剩余时间。
- 今日累计工作时长。
- 今日完成休息次数。

支持的操作：

- 开始计时。
- 暂停计时。
- 立即休息。
- 重置当前工作段。
- 查看设置。

计时规则：

- 计时基于真实时间差，不依赖渲染帧数。
- 应用最小化或切换窗口后，计时继续运行。
- 电脑进入睡眠后默认暂停计时，唤醒后不补算睡眠时间。
- 应用重启后不恢复未完成的工作段，避免状态不一致。

### 6.2 30 分钟重要提醒

触发条件：连续工作达到 30 分钟。

提醒方式：

- 桌面通知。
- 主窗口提醒状态。
- 系统托盘图标状态变化。
- 可选声音提醒。

提醒操作：

- `开始休息`：立即进入休息流程。
- `延后 5 分钟`：继续计时，并标记为已延后。
- `继续工作`：关闭当前提醒，但 40 分钟仍会触发强制休息。

建议文案：

> 已连续工作 30 分钟。现在休息 2 到 5 分钟，让眼睛离开屏幕。

### 6.3 40 分钟强制休息

触发条件：连续工作达到 40 分钟，且用户未完成休息。

行为：

- 打开全屏休息窗口。
- **多显示器：每一块屏幕各一个全屏休息窗**（2026-11-03 增补）——光标所在屏显示完整界面（倒计时+训练+小游戏），其余屏显示简洁镜像（大倒计时 + 「这块屏幕也在休息」提示），不给「扭头看另一块屏继续干活」留空隙。
- 窗口始终置顶。
- **息屏/唤醒自愈**（2026-11-03 增补）：息屏中触发强制休息时若全屏创建失败，窗口先铺满该屏尺寸打底；休息期间每 3 秒校验是否仍铺满，丢失即拉回整屏；唤醒、显示器参数变化时立即校验。
- 显示 5 分钟倒计时。
- **严格模式（默认）**：不提供跳过按钮；非严格模式：休息窗底部显示低调的「跳过本次休息」文字按钮（2026-11-03 增补）。
- 倒计时结束后才允许进入下一轮工作计时。

“强制”定义：

- 应用层面强制进入全屏、置顶的休息流程。
- 无法阻止用户强制退出应用、结束进程或使用操作系统级快捷键。

### 6.4 护眼训练

MVP 至少提供以下两种训练，并建议实现三种：

1. **远近切换**
   - 引导用户看向远处 20 秒，再看向近处固定点 10 秒。
   - 可循环 2 到 3 轮。

2. **缓慢追踪**
   - 显示缓慢移动的目标点。
   - 目标移动速度稳定，不使用快速闪烁。

3. **眨眼练习**
   - 引导用户缓慢眨眼 5 到 8 次。
   - 训练过程中允许闭眼或看向远处。

4. **呼吸引导**（2026-11-02 增补，李先生选定）
   - 4-4-6 拍节奏：吸气 4 秒（光环缓慢放大）→ 轻轻保持 4 秒 → 呼气 6 秒（缓慢缩小）。
   - 每拍切换有轻拍点音（吸气高音/呼气低音），闭眼只听节奏也能跟练。
   - 轮数按休息时长收敛（5 分钟约 10 轮），已加入自动轮换序列。

所有训练都必须提示用户：训练不是医疗治疗，过程中可以闭眼或移开视线，不需要持续盯住屏幕。

### 6.4a 休息背景声（2026-11-02 增补，李先生选定）

- 休息界面提供「雨声 / 溪流」两种白噪音，Web Audio 本地合成，不联网、无音频文件。
- 音量滑块可调，2 秒渐入 / 1.5 秒渐出防爆音；再点当前音源即关闭。
- 偏好（音源 + 音量）跨休息、跨重启记忆（渲染层 localStorage，仍在本地）。
- 休息窗口关闭声音随之停止；拍点音独立通道，不受白噪音音量影响。

### 6.5 休息小游戏

MVP 实现一个低刺激小游戏：**寻找远点**。

- 屏幕显示简洁提示和缓慢移动的目标点。
- 用户只需观察，不需要快速点击。
- 每轮 30 到 60 秒。
- 游戏结束后继续剩余休息时间。
- 训练与小游戏总时长不得超过本次剩余休息预算；短休息可减少训练轮数或省略游戏。自动轮换索引由主进程跨休息窗口保存，连续休息应实际切换训练内容。

不实现以下类型：

- 高频点击。
- 快速反应。
- 闪烁和强刺激视觉效果。
- 复杂关卡或需要长时间盯屏的玩法。

### 6.6 设置

设置项：

- 30 分钟提醒开关。
- 40 分钟强制休息开关。
- 强制休息时长，默认 5 分钟。
- 提醒声音开关。
- 自动训练开关。
- 训练模式：自动轮换、远近切换、缓慢追踪、眨眼练习、呼吸引导。
- 开机启动。
- 是否显示每日统计。
- 严格模式。

设置热应用规则：

- 关闭定时提醒时，当前提醒卡与尚未到期的延后提醒立即失效，不得在五分钟后重新出现。
- 提醒阈值高于强制休息阈值时联动收敛；设置面板必须展示主进程返回的真实生效值。
- 只有本地写盘成功后才提示“已保存”，失败必须明确提示且不得热应用未持久化配置。

严格模式说明：

- 开启：40 分钟自动进入全屏休息，不能通过应用界面跳过。
- 关闭：40 分钟显示休息界面，但允许用户手动跳过。
- 默认开启。

### 6.7a 桌面小时钟（2026-11-03 增补，李先生要求）

主窗口隐藏（后台运行）时，桌面显示一个半透明、置顶、可拖动的小时钟：

- 工作中：绿点 + 「工作中 · 距强制休息」+ 倒计时；该休息了/已延后：黄点；休息中：蓝点 + 休息剩余；未计时：灰点。
- 全屏强制休息开始时小时钟自动销毁（休息窗接管）；主窗口恢复可见时销毁；设置里可关（「后台时显示桌面小时钟」，默认开）。
- 内存策略（李先生明确要求）：**按需创建/销毁**——主窗可见的常态下小时钟进程完全不存在（renderer 进程数 1）；仅后台运行时段存在一个轻量渲染进程（页面包 0.7KB gzip）。位置拖动后记忆。

### 6.7 系统托盘

托盘菜单：

- 开始或暂停计时。
- 立即休息。
- 查看主界面。
- 打开设置。
- 退出应用。

托盘状态（2026-11-03 起图标为「眼睛」造型：眼白 + 状态色瞳孔，深浅菜单栏均清晰；四色语义不变）：

- 灰色瞳孔：未计时。
- 绿色瞳孔：工作计时中。
- 黄色瞳孔：30 分钟提醒已触发。
- 蓝色瞳孔：休息中。

## 8. 状态机

```text
idle
  -> working
working
  -> reminder30    达到 30 分钟
  -> forcedRest    达到 40 分钟
  -> paused        用户暂停
reminder30
  -> manualRest    用户开始休息
  -> extended      用户延后 5 分钟
  -> working       用户继续工作
extended
  -> forcedRest    总工作时长达到 40 分钟
  -> manualRest    用户开始休息
forcedRest
  -> working       5 分钟休息完成
manualRest
  -> working       手动休息完成
paused
  -> working       用户恢复计时
```

核心计时逻辑必须独立于 UI。UI 只负责展示状态和发出动作，计时器负责状态转移、时间校正和边界处理。

## 9. 本地数据

```ts
type UserSettings = {
  reminderMinutes: number;
  forcedRestAfterMinutes: number;
  forcedRestDurationMinutes: number;
  strictMode: boolean;
  soundEnabled: boolean;
  launchAtLogin: boolean;
  trainingMode: "auto" | "far-near" | "tracking" | "blink" | "breathing";
};

type DailyStats = {
  date: string;
  totalWorkSeconds: number;
  completedRestCount: number;
  longestWorkSessionSeconds: number;
};
```

默认只保存本地数据，不保存：

- 屏幕截图。
- 键盘输入。
- 鼠标轨迹。
- 正在使用的软件名称。
- 浏览记录。
- 云端账号信息。

## 10. 非功能需求

- 应用启动后可以长期驻留后台。
- 空闲时保持较低的 CPU 和内存占用。
- 最小化后计时仍然准确。
- 电脑睡眠和唤醒后的行为可预测。
- 休息动画不使用快速闪烁和高频变化。
- 优先支持 macOS，结构上可扩展到 Windows。
- 核心计时逻辑需要单元测试。
- 关键工作流需要端到端验证。

## 12. 明确不做

- 云端账号和多设备同步。
- AI 眼睛健康分析。
- 摄像头判断用户是否真的在看屏幕。
- 医疗建议或视力评估。
- 社交排名。
- 复杂游戏系统。
- 自动关闭用户正在使用的软件。
- 试图绕过操作系统权限来阻止用户结束应用。

## 13. 推荐技术方案

- Electron：桌面窗口、系统托盘、全局提醒、全屏置顶休息层。
- TypeScript：计时状态机和应用业务逻辑。
- Vite：前端开发和构建。
- 原生 CSS：控制布局、动画和全屏状态，减少依赖。
- 本地存储：优先使用 Electron Store 或轻量 JSON 存储。
